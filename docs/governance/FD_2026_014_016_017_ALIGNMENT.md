## 2. FD-2026-016 — purpose-based data access

Private/restricted/child-sensitive describes access, handling, disclosure, interpretation, and action boundaries. It is **not** an AI-blind rule.

Founder/authorized AI may READ, SYNTHESIZE, and ANALYZE real adult/child/customer operational data when task, purpose, and access are appropriate.

This does **not** mean background-ingesting all private data into a Machine Library. Default persistence/crawl may stay fail-closed. Protected on-demand source access is a separate capability and must be purpose-gated, access-gated, and auditable.

Knowledge != Permission. Read/understand permission does not imply permission to send, edit, delete, pay, change entitlement, publish, or perform high-risk actions.

For child data, retain safety boundaries: no diagnosis, labeling, deterministic career/mission/future prediction, or fixed psychological profiling.

## 4. Repository synchronization rule

Repository is the **live implementation ledger**. Google Drive library must not mirror every commit.

Sync a semantic milestone to Drive when one of these changes materially:

- Founder authority or approved contract;
- architecture, security/data model, or Project/System ownership;
- canonical route/public behavior;
- release lifecycle: Draft -> Merged, Preview -> Production, activation/deactivation, rollback/incident;
- dependency/blocker that changes Founder action;
- repository governance for agents.

Do not create Drive churn for routine commits, refactors, formatting, comments, temporary test state, Draft PR head changes, or preview rebuilds that do not change approved state.

Every task that depends on implementation must query repo state live and report checked-at, branch/PR/head SHA, Draft/Merged, and Preview/Production.
